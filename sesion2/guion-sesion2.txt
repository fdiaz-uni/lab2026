4. Patrón de diseño MVC (Model View Controller): Patrón general, aplicable a muchos casos en desarrollo web, total o parcialmente. 
MODELO, componente software que encapsula (en forma de función/método dentro de un script/objeto PHP) las consultas de BBDD sobre una única entidad del modelo de datos, habitualmente asociados a casos de uso CRUD (Create, Read, Update, Delete). VISTA, típicamente formularios (editables o no, vacíos o precargados) de entidades individuales, índices con conjuntos de instancias de una entidad, ambos con controles de acción para procesar información. Habitualmente se generan como consultas a partir del modelo de datos. CONTROLADOR, script/código PHP que discrimina qué tipo de acción se realiza sobre la entidad (que se puede pasar como parámetro en la URL petición como query string o como input oculto del formulario) y redirigir a la siguiente página.

5. Patrón de diseño PRG (Post-Redirect-Get): Específico para tratar formularios asociados a acciones que implican un cambio en el estado persistente del servidor.
Get formulario registro. Después de petición GET, hacer petición POST para procesar datos del formulario tras submit. El script invocado para procesar datos formularios, deberá realizar una redirección HTTP por programa. Las peticiones POST (que no devuelven contenido HTML) no se cachean por parte del navegador (y por tanto no se guardan datos de peticiones POST anteriores), no se introducen en el historial del navegador (y por tanto no se pueden reactuar peticiones de procesamiento de información metiante peticiones POST hechas con anterioridad). 
A efectos prácticos: i) siempre se hace una petición POST después de una petición GET, y ii) de una petición POST a una petición GET se pasa a través de una redirección en la respuesta del POST.

9. Prevención inyección de código JS y SQL. Saneamiento de todas las entradas recibidas en el lado servidor. Inclusión de "inc/codigo_funciones.php" en plantilla genérica. Si se previene inyección JS (ataques XSS), básicamente se sanean las entradas con "htmlspecialchars()", aparte de otros filtros adicionales, stripslashes() y trim(). 
ATENCIÓN!!!La función htmlspecialchars() es una de las herramientas de seguridad más importantes en PHP para prevenir ataques de Inyección de Código JavaScript (XSS o Cross-Site Scripting). Su objetivo principal es transformar caracteres especiales de HTML que el navegador podría "ejecutar" (como < o >) en texto plano inofensivo (entidades HTML como &lt; o &gt;).
Ejemplo: Si la entrada modificada por un usuario es:
'><script>alert("ko")</script>
Al pasar por htmlspecialchars(..., ENT_QUOTES, 'UTF-8'), PHP la transforma internamente en:
&#039;&gt;&lt;script&gt;alert(&quot;ko&quot;)&lt;/script&gt;
Para prevenir la inyección SQL se realizarán CONSULTAS PREPARADAS mysql (técnica preferida). [ver ejemplos del modelo]
